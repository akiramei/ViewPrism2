# impact-prospective-01 — 前向き評価の手順(次の実変更で起動・2026-09-05 固定)

主題: **既に BOM にある情報を変更判断へ利用できるか。** 次の実変更(ECO-082 の着手、または新規の変更要求)の起票時に、
現状の BOM だけからの予測と、独立に封印した裁定・実 diff を突合し、**BOM の参照箇所が各判断をどう支えたかを項目別に残す**。
実験のための製品変更は行わない。改善者の指示比較(v1/v2)は行わない(保留・EXP-20260905-04)。

## 起動条件(トリガー)

- maintainer から変更要求(不具合報告・要求変更)が出た時点で、**ECO 起票より前に**本手順を開始する。
- 起動しなかった場合は「機会あり・非起動」として記録する(散文契約の非起動は観測対象)。

## 手順

1. **固定**: 変更要求 R(maintainer の原文。診断・実測・箇所名を含めない)と baseline(HEAD sha)を `cases/<ECO or CR id>/REQUEST.md` /
   `BASELINE.txt` に書き、sha256 を記録する。以後この 2 つは変えない(追記のみ)。
2. **予測者パッケージ**(履歴なし・許可ファイル集合): R + baseline 時点の BOM 一式(10/20/30/31/32/33/34/53)。コードは含めない。
   様式は `briefs/TASK-PREDICT-v2.md`(製品 unit と検査 unit を分け、**判断ごとに BOM の参照箇所を必須**)。
   実行: Codex Sol medium × 2 反復(pilot-01 と同条件)。effort-trial-runner の `execute --package` で receipt を残す。
3. **裁定者**(独立・予測を見ない): R + baseline のコード + M-BOM の artifact 表(id/path のみ)。様式は `briefs/TASK-ADJUDICATOR.md`
   (製品 unit / 検査 unit を分けた版)。**予測より前、かつ実装より前に**封印(sha256)。
4. **実装は通常どおり**(ECO 起票→fix→accept)。本手順は実装に介入しない。
5. **突合**(製造者= claude・実装完了後): 予測 × 封印裁定 × 実 diff を突合し、`cases/<id>/LEDGER.md` に**項目別台帳**を書く:

   | 判断項目 | 予測の値 | 予測が引いた BOM 参照箇所(file:id:field・引用) | 参照の支持度 | 封印裁定 | 実 diff | 訂正・備考 |
   |---|---|---|---|---|---|---|

   - 判断項目= 変更が必要な製品 unit / 調査すべき製品 unit / 変更が必要な検査 unit / 確認すべき契約・検査(CP) / 非影響とその根拠 / 未確定。
   - 参照の支持度= `supported`(参照箇所の記述がその判断を直接支持)/ `partial`(手がかりのみ)/ `unsupported`(参照はあるが判断を支持しない)/
     `none`(BOM を引かず一般知識)/ `contradicted`(参照の記述と判断が矛盾)。
   - 裁定の訂正は `ADJUDICATION-HISTORY` 様式(初回は不変・訂正は追記・過大判定は裁定の訂正として明示)。
6. **記録**: trial(receipt)・封印物・台帳・監査(コマンドはパッケージ内か)を `cases/<id>/` へ。private path はマスク(pre-commit 監査)。

## 測るもの / 測らないもの

- 測る: 判断項目ごとの「BOM の参照箇所が支持したか」の分布(supported / partial / unsupported / none / contradicted)、under / over、
  予測が引いた BOM の場所の種類(過去事例の記録・契約・依存・CP)。
- 測らない: BOM 改善の効果(改善は行わない)/ effort の効果(副評価にも入れない)/ 指示様式の効果(v1/v2 比較は保留)。

## 役割の独立性

- 予測者・裁定者は Codex の独立セッション。製造者(claude)は封印・突合・台帳のみ。起票・実装の担当が予測を見てから実装すると
  予測が実装に影響する(汚染)ため、**予測結果は実装完了まで実装担当に開示しない**。
